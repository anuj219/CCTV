why not noSQL for fast RnW-
    NoSQL (MongoDB, CouchDB, Redis): Every write involves packing a payload (BSON/JSON), making a TCP loopback request to localhost:27017, context-switching between processes, and waiting for an ACK.

Tried ArcFace + Insight Face Architecture
    InsightFace: An open-source 2D and 3D deep face analysis toolkit/framework that provides
        a full suite of tools for computer vision tasks, including detection, alignment, and recognition.
        Implements Arcface and has Retinaface as a module
    ArcFace: additive angular margin loss function and embedding method
        designed specifically for identity recognition and more robust to CCTV pose and lighting
        creates the 512 dimensional vector using a NN
        FaceNet uses trplet loss, whereas ArcFace uses Additive Angular Margin Loss
            designed to make better clusters
            transforms classic softmax loss into geometric margin based function
            works in angular space to force larger margin between classes, pushing embeddings apart, based on angle, rather than distance alone
            it normalizes embeddings and class weights, making classification largely depend on margin
            thus, small differences in angle make big impact
        ArcFace does produce clusters of embeddings for each identity, but clustering is not the training objective.
        it typically does - I already know which identity each image belongs to. just Learn an embedding space where images of the same identity align closely and different identities are separated by an angular margin.

        Yolo detects person
        InsightFace's RetinaFace module, detects the actual face
        facial landmarks align the face
        ArcFace creates a stronger 512-D identity embedding (instead of dlib's 128D)
        compare against multiple enrolled embeddings
        pool embeddings across tracked frames
            several observations of the same person are averaged, reducing noise from individual frames
        the result must remain consistent across multiple observations.
    
    main change : InsightFace RetinaFace + aligned ArcFace face crop

    new pooling:
        each tracked person stores up to 5 ArcFace embeddings (track["embeddings"].append(face.embedding))
        Pooling calculates their average
        So instead of matching one noisy frame, it matches a representation of the person across several frames

        gallery/db has prototype for each person
            i.e average embedding + closest individual enrollment embedding

    Flow
        Gallery/db creation
            each person's usable image is converted to embedding using retinaFace+Arcface method
            Also, prototype is create which is the average of all embeddings for a person
            thus, Anuj:
                individual embeddings: E1, E2, E3
                prototype: average(E1, E2, E3)

        Live, 
        As Anuj moves, the tracker collects live embeddings

        InsightFace processes the frame
            uses RetinaFace internally to find actual faces and landmarks (returns face bounding box)
            InsightFace generates one vector for that face, which has 512 numbers
            code stores up to five such embedding vectors (track["embeddings"].append(face.embedding))

        matching
